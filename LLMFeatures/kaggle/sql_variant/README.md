# Отдельный Kaggle-эксперимент: Llama → SQL → LightGBM

Импортировать **`../llmfe_llama31_hm_sql_kaggle_t4.ipynb`** как новый Kaggle Notebook.
Достаточно одного .ipynb: evaluator, SQL engine и runtime встроены в него.
Input прежний: `hm_llmfe_kaggle_fulltrain_v2.zip`. GPU T4, Internet включён.
`MODEL_SOURCE` выбирает `unsloth` или официальный `hf`, как в pandas-версии.
Для сравнения используйте одинаковые MODEL_SOURCE и MODEL_REVISION в обоих запусках.

Интерфейс как у локальной Qwen: JSON с `aggregates` (до24) и `derived` (до12).
Агрегат содержит `name`, `keys`, `sql`; формула содержит `name`, `sql`.
Формулы видят15 исходных полей, агрегаты и ранее определённые формулы.
LLM выбирает все признаки; host выполняет группировки и LEFT JOIN, сохраняет порядок строк.
Это ограниченные SQL-выражения, не произвольные SQL-запросы и не Python-код.
Допустимые имена/функции проверяются; внешний доступ DuckDB отключён.

Прежние803377 train пар /50000 user-time /52 снимка, неизменные кандидаты ID-GNN.
Search256 /confirmation512 /heldout val1024 /test2048 пользователей.
LightGBM150 rounds/31 leaves, seed42, до4 CPU threads. История180 дней до cutoff.
Три популяции, цель20 различных оценённых наборов, максимум300 обращений,
до3 исправлений каждого предложения. Smoke/preflight/ошибки/дубликаты не входят в20.
Raw control может победить; итог явно отмечает отсутствие выбранных LLM-признаков.
Сравнения, гистограммы, кривые обучения и независимый replay сохранены.

Это отдельный протокол `hm_llmfe_llama31_8b_lightgbm_sql_fulltrain_v1`, собственный
каталог результатов и `llmfe_sql_runtime`. Текущий pandas-ноутбук и его результаты не меняются.
Параллельный запуск — в отдельном Kaggle Notebook, при доступной квоте GPU.
Близость интерфейса к Qwen не означает идентичность всего эксперимента:
другие LLM/промпт, история ограничена когортой и180 днями, другой бюджет/выборки.

Смотреть `candidates/candidate_*/program.json`; `program.py` содержит тот же JSON
для совместимости общего evaluator. Ответы, ошибки, популяция и исправления — в `trial.json`.
Строка `ACCEPTED` печатает search MAP; `REJECTION` печатает причину отказа.

Локальные проверки используют тестовые SQL-программы, а не генерацию Llama.
`check_sql.py` проверяет формулы, порядок, missing groups, запреты, временные границы и notebook.
`check_pipeline.py` проверяет ошибки/repair/duplicate/resume/final replay с настоящим LightGBM
на малой выборке, затем803377 train пар и сохранённую модель на heldout val-пуле.
Качество настоящей Llama станет известно после запуска на Kaggle.
