# Предлагаемые следующие опыты TDM, 2026-10-17

Это предложения в ответ на вопрос пользователя. Новые запуски не разрешены
этим вопросом и не выполнялись. Текущий отдельный LLM-поток не изменяется.

Основа: fixed native test MAP1.395195%, full теми же весами1.002919%;
cluster native0.551263%. Один seed, test250; причины различий не установлены.
Восемь replay проверили воспроизведение, но не доказывают оптимальность
нашей weekly loss/negative sampling/архитектуры.

1. Диагностика без обучения на validation: beam16/32/64/128/256/full,
   MAP@12, Recall@50/100/200, доля недельных целей, сохранивших путь на
   каждом уровне, распределение полно-каталожных рангов целей, coverage
   и персонализация. Дополнительно перемешать историю между пользователями
   при сохранённых целях: проверить вклад истории; это абляция инференса,
   а не обученный контроль. Снижение MAP при расширении beam возможно:
   внутренний отбор может фильтровать ложные высокие листовые scores.
2. Сопоставимый DNN без дерева: та же attention/history модель и leaf
   embeddings, обучение только листовым целям. Новый TDM-контроль с теми же
   leaf-негативами/позитивами/seed, сопоставимым бюджетом. Для обоих выбрать
   checkpoint по одному full-validation критерию, сравнить full-leaf MAP;
   дополнительно native beam TDM. Старый full результат уже обученного
   TDM не заменяет leaf-only обученный контроль. Внутренние embeddings и
   дополнительное обучение уровней — часть изменения, не идентичная ёмкость.
3. Наша weekly adaptation как отдельная гипотеза: сначала при фиксированном
   sampling изменить равные веса уровней на акцент листового уровня;
   затем отдельным опытом при фиксированном loss изменить распределение
   негативов по уровням в пользу нижних, сохранив суммарный бюджет.
   Везде исключать все положительные предки недели. Не менять оба фактора
   сразу, не предполагать, что текущая loss тождественна статье.
4. Дерево и сигналы: случайное сбалансированное дерево против category-based
   при одинаковом scorer; затем отдельно добавить статические атрибуты H&M
   в scorer, поскольку текущая модель history-only. Одинаковое добавление
   атрибутов проверить для leaf-only DNN. Рост обоих означает вклад признаков,
   не автоматически преимущество дерева. Рост эффекта истории при большей
   истории также измерять, не объяснять им текущие результаты заранее.
5. Если предыдущие проверки дали сигнал: сначала представление истории
   предками соответствующего уровня при фиксированном дереве (компонент
   JTM-H), затем отдельно objective-based перестройка JTM. Простое повторение
   KMeans не является JTM. Потом расширить train при том же каталоге/val/test,
   если доступно прошлое исходного H&M; не смешивать этот опыт с расширением
   каталога. Для проверки масштабирования отдельный ряд размеров каталога
   и одинаковая когорта/cutoffs; качество между разными каталогами напрямую
   не сравнивать. Измерять реальное время и полную стоимость индекса.

Приоритет:1→2→3. Последующие этапы условные. Перспективный вариант повторить
минимум на3seed; отделить seed обучения от seed дерева/данных. Нынешний
test многократно просмотрен: выбирать настройки по validation, а для
подтверждения подготовить дополнительный временной holdout без использования
его будущих транзакций в обучении/индексе; учесть, что он меняет протокол.

Критерий потенциала дерева: преимущество качества над сопоставимым DNN
либо близкое качество при меньшей измеренной стоимости поиска. Улучшение
над собственным слабым первым запуском само по себе недостаточно.
