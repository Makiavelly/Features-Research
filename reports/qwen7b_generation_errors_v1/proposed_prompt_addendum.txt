PROPOSED ADDENDUM — NOT AN EXECUTED EXPERIMENT
Keep the existing SQL/JSON interface, complete feature sets and evaluation protocol.

There are TWO DIFFERENT namespaces:
1. aggregates[].sql sees ONLY history columns: customer_id/article_id for allowed
   counts, price, days_ago, sales_channel_id, customer_age, purchased-article categories.
   No raw_* fields exist here. The host owns GROUP BY and joins.
2. derived[].sql sees ONLY raw_u_*/raw_i_* fields, aggregate feature names and
   EARLIER derived names. No days_ago/price/customer_age/product_code columns exist
   here. It must compute one scalar PER CANDIDATE ROW, not aggregate rows.

Numeric output only. For a static age bucket use derived:
CASE WHEN raw_u_age < 20 THEN 0 WHEN raw_u_age < 40 THEN 1 ELSE 2 END
Never return 'young', 'middle' or other SQL strings.

Allowed keys are EXACTLY:
- [customer_id]
- [article_id]
- [one purchased-article category]
- [customer_id, article_id]
- [customer_id, one purchased-article category]
No three-key groups. No price/days_ago/customer_age/sales_channel_id grouping.
To summarize historical channel1, use keys=[customer_id] and
count(*) FILTER (WHERE sales_channel_id = 1)
The future candidate has no sales_channel_id to join on.

No OVER/PARTITION BY/ROWS/window functions or full queries.
Most recent purchase: min(days_ago) inside an aggregate with chosen keys.
If using mode, put ORDER BY INSIDE parentheses:
mode(customer_age ORDER BY customer_age)
Do not write mode(customer_age) ORDER BY customer_age.

To compute a recent purchase share, FIRST define aggregates:
f_purchase_count: keys=[customer_id], sql=count(*)
f_recent_count: keys=[customer_id], sql=count(*) FILTER (WHERE days_ago <= 7)
THEN define a derived scalar:
f_recent_count / nullif(f_purchase_count, 0)
Do not use sum(days_ago), min(days_ago) or other history operations in derived.

Names must describe the actual statistic: sum(price) is spending, not a discount;
count(distinct product_code) is diversity, not transaction count.
Return one COMPLETE JSON program, no Markdown. These examples illustrate syntax;
their predictive quality has not been measured.
