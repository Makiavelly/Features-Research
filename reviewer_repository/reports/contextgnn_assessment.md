## Вывод и архитектура

Подход непосредственно применим: авторы уже оценивали нашу задачу
rel-hm/user-item-purchase. Те же временные границы и MAP@12 подходят.
Для локальных товаров модель использует user-conditioned GNN признаки;
вне подграфа — GNN user vector × shallow item vector. Пользовательский
обучаемый offset согласует шкалы. Ветви используют один GNN backbone
и обучаются совместно cross-entropy. Это не ансамбль наших готовых весов.

Реализация construct_logits имеет расширенный локальный score:
linear head + dot пользовательского/локального товарного вектора,
плюс offsets обеих ветвей. Не сводить её к усреднению двух score.
Глобальная товарная ветвь не требует запуска отдельной GNN на товаре.
Модель покрывает весь каталог, но локальные pair embeddings всё ещё
существуют только внутри sampled subgraph. Другие пары оценивает fallback.

## Связь с автоматическими признаками для дерева

Статья оценивает нейросетевое ранжирование. ContextGNN → LightGBM —
отдельная наша гипотеза: глобальные user/item признаки для всех пар,
индикатор локальности и локальные признаки там, где они доступны.
Нельзя просто подставить нули вместо локальных векторов и утверждать,
что ContextGNN создаёт полноценные локальные embeddings всех пар.

## Ограничения

Lookup-таблица не даёт обученных векторов новым товарам. В §4.4 авторы
предлагают сеть на характеристиках товара; код содержит LOOKUP/FEATURE/FUSION.
Это отдельный режим/абляция, без обещания улучшения.
Библиотеки не устанавливались, обучение и скачивание весов не запускались.
