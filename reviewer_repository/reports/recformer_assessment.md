# Recformer: предварительная оценка для малого H&M

2026-10-16. Анализ источников и локальной схемы; обучения нет.

Цель пользователя: исследовательский отчёт; сравнение подходов на H&M;
RTX3060 6GB или KaggleT4; желательно не более часа на эксперимент.
Предпочтителен замороженный data/rel-hm-small-v1 из ContextGNN пилота.

## Источники и доступность

- Статья: https://arxiv.org/html/2305.13731
- Авторский репозиторий: https://github.com/JiachengLi1995/Recformer
- Репликация по ссылке авторов: https://github.com/AaronHeee/RecFormer

Авторский репозиторий содержит только README: код не опубликован из-за
политики Amazon. Скрытая комментарием документация raw README не доказывает
наличие исходников. В репликации доступны модель, токенизатор, dataloader,
collator, finetune и preprocessing. README содержит ссылки на GoogleDrive
checkpoints, но скачивание, происхождение и совместимость весов не проверены.
Нельзя называть их проверенными авторскими checkpoint.

## Метод и особенности кода

Товар кодируется текстовыми парами key/value. История становится
последовательностью текстов, свежие товары первыми. Longformer с позициями
товаров и типами токенов выдаёт CLS-вектор истории; тот же энкодер выдаёт
вектор отдельного товара. Ранжирование использует cosine similarity.
Pretraining: MLM плюс контрастивная задача истории/следующего товара.
Finetuning обновляет кэш товарных векторов по эпохам на стадии1, затем
фиксирует выбранный кэш на стадии2. Генерации Python-признаков нет.

Проверены finetune.py, dataloader.py, collator.py, recformer/models.py,
recformer/tokenization.py и finetune_data/process.py:

- finetune.py:1024tokens,3attributes,32tokens/attribute,50items.
  README предлагает256/512tokens; эффект на H&M неизвестен.
- fullsoftmax включается при finetune_negative_sample_size<=0,
  но CLI по умолчанию задаёт1000sampled negatives.
- Случайные negatives могут включать target; для наших многопозитивных
  целей этот путь нельзя переносить без адаптации.
- finetune.py оценивает test до обучения; наш wrapper должен оставлять
  test для финальной оценки после выбора по validation.
- Родной preprocessing использует leave-one-out и случайно оставляет
  часть пользователей; вместо него нужен наш subset manifest.
- Совместимость зависимостей ещё не проверена. Unsloth и действующее GNN
  окружение менять не нужно: при необходимости отдельное окружение.

## Предлагаемая адаптация, ещё без запуска

Сохранить train4804/val304/test250 user-times и каталог5000.
Текст товара: title=prod_name; category=product_type_name/product_group_name/
section_name; description=colour_group_name/graphical_appearance_name/detail_desc.
Все поля проверены в локальном article.parquet. ID только для индексации.

История каждой строки ограничивается её разрешённым cutoff. Для равных
дат нужен воспроизводимый технический порядок: реальное внутридневное время
неизвестно. Повторные покупки сохраняются и разрешаются при рекомендации.

Перенос loss: среднее -log fullsoftmax по уникальным позитивам недели,
затем среднее по user-times. Это адаптация, не точный objective статьи.
Оценка: все5000товаров, top12, прежний evaluator MAP@12; выбор только по val.
Checkpoint сохранять вместе с соответствующим item cache: в стадии2 он
намеренно фиксирован и не совпадает с новым encode текущими весами.

Сначала проверить pretrained checkpoint и zero-shot контроль, затем короткий
двухстадийный finetune с256tokens, FP16 и batch по памяти. Бюджет обеих стадий
определить после короткого timing/memory probe.512tokens — другая конфигурация.
Сохранить hashes, конфиг, кривые, полные прогнозы и независимый replay
из checkpoint и item cache. Скачивание/подготовку и обучение/оценку учитывать
отдельно; время до часа пока не подтверждено замерами. Полное pretraining
статьи не соответствует доступному часовому бюджету.

Test MAP@12 малого пилота, проценты: ContextGNN3.01558, IDGNN2.65341,
manualLightGBM1.23388, IDGNN-LightGBM0.96667, two-tower0.68368.
Сравнивать только на неизменном малом наборе. Один seed/250test пользователей
ограничивают устойчивость вывода. Внешнее pretraining Recformer учитывать
в отчёте. Не подбирать подход/настройки по повторному просмотру test.
