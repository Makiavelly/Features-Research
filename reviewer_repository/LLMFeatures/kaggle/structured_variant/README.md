# Llama: структурированные признаки → SQL → LightGBM

Импортировать `../llmfe_llama31_hm_structured_kaggle_t4.ipynb` в отдельный Kaggle Notebook.
Включить GPU T4 и Internet, подключить прежний `hm_llmfe_kaggle_fulltrain_v2.zip`.
Ноутбук самодостаточный, дополнительные .py загружать не требуется.
Выбор MODEL_SOURCE=`hf`/`unsloth` сохранён. Для hf нужен одобренный доступ и HF_TOKEN.
При сравнении с предыдущими запусками выбирать ту же модель/ревизию.

Новый протокол: `hm_llmfe_llama31_8b_lightgbm_structured_fulltrain_v1`.
Новый каталог runtime: `llmfe_structured_runtime`. Предыдущие ноутбуки не изменяются.
Это отдельный язык признаков, более ограниченный, чем SQL-интерфейс локальной Qwen.

LLM возвращает JSON с максимум24 агрегатами и12 производными формулами.
Пример описания (не добавляется в итоговые признаки автоматически):

```json
{
  "aggregates": [
    {"name":"f_recent","keys":["customer_id"],"op":"count","column":"*","window":30}
  ],
  "derived": [
    {"name":"f_recent_log","expr":{"op":"log1p","args":[{"ref":"f_recent"}]}}
  ]
}
```

Операции агрегатов: count/count_distinct/sum/avg/min/max/stddev_pop/median.
count использует column="*"; числовые агрегаты — price/days_ago/customer_age.
count_distinct также может считать уникальные ID/категории/каналы.
Ключи группировки: customer_id, article_id, категория одежды, либо customer_id+article/category.
Окно: целое1..180 дней. Поле window можно опустить (180 по умолчанию).
Производные формулы — числа, ссылки {"ref":...} или операции с args.
Унарные: abs/log1p/sqrt/negate. Бинарные: add/subtract/multiply/divide/min/max/coalesce.
Ссылки только на15 исходных полей, агрегаты и ранее определённые формулы.
Деление на ноль даёт пропуск; log1p/sqrt ограничивают отрицательный вход нулём.
Глубина дерева<=6, максимум64 узла на формулу, конечные константы +/-1000000.

Ни SQL, ни Python Llama не пишет. Все выражения SQL компилирует наш код;
группировки/LEFT JOIN/порядок строк контролируются host. Внешний доступ DuckDB отключён.
Это **не маска токенов и не grammar-constrained decoding**: обычный sampling JSON,
затем строгая проверка структуры. Возможны неверный JSON/неизвестные операции/ссылки.
Проверка собирает несколько ошибок сразу; LLM получает полный предыдущий ответ и ошибки.
Начальный промпт рекомендует компактный набор3–6 агрегатов/1–3 формулы, не уменьшает пределы24/12.

Остальной протокол прежний: seed42,803377 train пар, LightGBM150 rounds/31 leaves,
до4 потоков, search256/confirm512/heldout val1024/test2048 пользователей и общие кандидаты ID-GNN.
Три популяции,20 различных оценённых наборов, до300 обращений, до3 исправлений предложения.
Preflight/ошибки/дубликаты/raw-control не считаются в20. Raw control может победить.
Графики поиска/распределений/AP, сравнения с manual/GNN-LightGBM/ID-GNN и независимый replay сохранены.

Артефакты кандидата: program.json — исходное структурированное описание,
compiled_sql.json — созданные host SQL-выражения, trial.json — статус/метрики/ошибка,
response.json/prompt.txt — ответ и запрос Llama. program.py дублирует JSON для совместимости хранения.
В логах ACCEPTED с search MAP и REJECTION с причиной. Финальный ZIP скачивается из Output.

Проверки используют синтетические ответы и настоящую CPU-модель LightGBM.
Они подтверждают работу ПО, а не качество или успешность генерации настоящей Llama.
