# H006: GPT-6.1 Sol пишет Python-признаки

Отдельный эксперимент после H005 (полный SQL), без изменения его результатов.
Модель `gpt-6.1-sol`, Tooken Club, те же temperature=0.8, top_p=1,
reasoning_effort=low, max_tokens=2048, seed=42+номер_обращения−1 (гарантии seed у провайдера нет).
До 300 фактических POST, цель — 20 структурно разных полностью оценённых программ,
до трёх исправлений; три популяции с лучшей программой в контексте.

Модель пишет полную `modify_features(X, history)` на pandas/NumPy, с helper-функциями
и константами. X — идентификаторы пары и 15 исходных полей; history — все доступные
прошлые покупки 5000 пользователей с характеристиками купленных товаров.
Историю физически отсекает host до вызова функции, цели/будущие покупки не передаются.
Результат — до 36 новых числовых f_* столбцов в порядке строк X; исходные 15 полей добавляет host.
Столбцы выравниваются по именам относительно первой схемы; строки host не переставляет.
В промпте есть рабочий начальный пример, полный список полей и search MAP лучшей программы.

Те же 72813 пар / 4804 user-times / 8 cutoffs / LightGBM binary150,31leaves,4threads.
Search128 × весь каталог5000 → top3+raw на confirmation88 → заморозка победителя →
heldout88 / val304 / test250. Test ранее просматривался: повторная диагностическая оценка.
Наборы не выбираются по test. Исходный raw контроль обязан побайтно совпасть с H005.

Проверка Python: parse+compile, ограничения I/O/случайности, тип/схема/индекс результата,
перестановка строк и разбиение на батчи на раннем/позднем train-cutoff;
в v2 также обязательны пустая история и отсутствующие группы.
На функцию 60 секунд, весь worker 1800 секунд и 8GiB адресного пространства.
Работа идёт в отдельном CPU worker с ограниченными builtins, но AST-проверка **не является
защищённой песочницей для враждебного Python**. Это проверка обычного модельного кода.
Нет белого списка методов pandas/NumPy: запрещены I/O, eval/query и приватные атрибуты.

Перед генерацией — регрессия на корректных и ошибочных программах, независимые числовые
ответы, сравнение Python/SQL на реальной истории, совпадение raw кодировок и past-only истории.
Для каждого реального отказа сохраняются prompt/response/source, stage, traceback/diagnostics.
Аудит должен отдельно классифицировать ошибки модели, нарушения контракта и ошибки host.
Тесты не доказывают отсутствие всех ложных отказов. Если найден дефект валидатора,
исходный поток сохраняется; исправление имеет новый ID и явно описанную процедуру replay.

Дедупликация консервативная по Python AST без комментариев/пробелов/docstrings;
она не доказывает различие числовых матриц или алгебраических выражений.
Сравнение с SQL меняет язык, интерфейс и примеры в промпте. Один прогон не изолирует
их причинные эффекты; качество и валидность программ оцениваются отдельно.
Пользователь уточнил: используемые агрегаты можно выразить и на SQL. Это верно;
гипотезы о превосходстве Python как языка здесь нет. Проверяется эффективность
модельного поиска через другой интерфейс. Одинаковые числовые матрицы и настройки
LightGBM дают одинаковое обучение; язык генерации сам по себе преимуществ не создаёт.

Секрет только из корневого .env; заголовки Authorization не сохраняются.
До первой генерации пройдено28 проверок. Дополнительный разбор выявил другой порядок тех же
столбцов на пустой истории вcall5: исходная проверка этого случая не включала, хотя промпт
требовал стабильной схемы. Исправленная v2 нормализует порядок по именам и проверяет empty/absent
до обучения. Версияv2 прошла29 регрессий; непустые матрицы первых8ответов совпали сv1 на8cutoffs.
V1 сохранена, перенос не сбрасывает общий лимит300POST; первые8ответов не генерируются повторно.
Это один продолжаемый поток с изменением host-проверки, не независимый LLM прогон.

Неограниченный exec модельного кода был отклонён автоматической проверкой безопасности
и не выполнялся. Дополнительный разбор использует прежний ограниченный wrapper;
отдельно написанные аудитором SQL эталоны подтвердили28 признаков двух реальных ответов по8cutoffs.

Запуск: `LLMFeatures/run_provider_python.py`; проверка: `check_python_features.py`,
`review_python_validator.py`, `check_python_numeric_references.py`.
