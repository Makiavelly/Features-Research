# H007: текущая сессия Codex сама строит ровно20 наборов

Пользователь поручил написать и проверить ровно20 наборов, отдельно от API провайдера.
После уточнения пользователя используется **адаптивный поиск по трём популяциям**:
наборы идут циклически0/1/2, итого7/7/6. Родитель — лучшее уже оценённое решение
своей популяции поsearch MAP@12, либо исходный raw контроль. Каждое решение и его
обоснование фиксируются с хешем до получения его search-оценки.

Первоначально были написаны20 неоценённых тематических черновиков; ни один не был
обучен/оценён до уточнения режима. Они сохранены как черновики, а не расписание
эксперимента. Только отдельно зафиксированные адаптивные предложения становятся
кандидатами. Ни автоматического перебора комбинаций, ни скрытых дополнительных
обучений для выбора этих20 нет. Общие helper-функции — реализация признаков,
не дополнительные оценённые наборы. Синтетические проверки не обучают LightGBM
и не считают search/confirmation/test метрики.

Данные и downstream прежние: small-v1,72813 train-пар/4804 user-times/8cutoffs,
LightGBM binary150rounds,31leaves,4CPU,seed42; до36 новых числовых признаков + raw15.
Search128 пользователей × весь каталог5000; после20 наборов top3search + raw
сравниваются на confirmation88. Победитель замораживается до heldout88/val304/test250.
Один и тот же raw контроль переиспользуется из H006 — это не21-й новый авторский набор.

Программы исполняются тем же Python FeatureEngine/worker/валидатором, что H006v2:
past-only history, numeric/schema/index, permutation/batch/empty/absent проверки,
таймаут60секунд, worker8GiB/1800секунд. Полные train-матрицы хешируются без меток:
проверяется числовое отличие от всех предыдущих наборов, не только отличие текста.
Работа валидатора дополнительно проверена на ручных числовых примерах, включая
затухание и граф совместных покупок категорий. Внешних API вызовов0; .env не читается.

Ограничения сравнения: точный движок текущей сессии не аттестован; нельзя утверждать,
что это проверенная эталонная GPT-6.1 Sol. Я знаю всю историю и прежние результаты.
Контекст, возможность пользоваться инструментами и объём кода не равны API-промпту
с2048выходныхтокенов; этот лимит здесь не имитируется. Новое сравнение может показать
разницу результатов, но не доказать/опровергнуть подмену модели провайдером.
Test ранее просматривался, поэтому это повторная диагностическая оценка, не новый blindtest.

Файлы: authored20_design.py — общий написанный код и исходные черновики;
authored20_proposals/NNN.json — конкретные решения по ходу поиска;
run_authored20.py — фиксация, оценка и контроль точного числа20;
commit_chain.jsonl — проверяемая цепочка фиксации до оценки.
