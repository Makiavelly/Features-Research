# H008: GPT-6.1 Sol API — только признаки, возвращённые моделью

Новый независимый API-поток; модель/провайдер, данные, настройки LightGBM и память
поиска совпадают с H006. Единственное содержательное изменение входа дерева:
15 статических raw-полей больше не добавляются автоматически. Они доступны
модели как вход функции; явно вернуть выбранное поле под именем f_* разрешено.

- Провайдер: https://tooken.club/v1, запрашиваемое имя gpt-6.1-sol.
- 72813 сохранённых train-пар / 8 cutoff, весь каталог 5000 товаров.
- LightGBM binary, 150 раундов, 31 лист, 4 потока, seed42; остальные параметры H006.
- 20 успешно оценённых программ, до300 фактических API POST, до3 исправлений.
- 3 популяции. Как H006: round-robin по предложениям, исправления в той же
  популяции; в промпте лучший код своей популяции и ошибки текущего предложения.
  Полная память всех попыток не добавляется в этом эксперименте.
- Дедупликация структурная AST как H006. Численно различающиеся матрицы считаются
  отдельно при аудите:20 программ не следует автоматически называть20 уникальными
  по значениям наборами.
- Контроль: одна константная f_control. Путь raw_control — только совместимость
  со старым оценщиком; исходных raw-признаков в этой модели нет.
- Search128 → top3+константный контроль → confirmation88 → заморозка выбора →
  heldout88 / полный validation304 / test250. Test ранее использовался в проекте.
- Не изменяются старые запуски или окружение unsloth. Токен только из .env,
  в логах запросов Authorization не сохраняется.

До API проверяются старые синтетические проверки валидатора, отказ нулевой
матрицы, точное совпадение сгенерированной части старого движка на8 cutoff,
порядок строк/батчинг/пустая история, контроль на одной константе и AP@12.
Никакие тестовые метрики не используются в этих проверках.

Реальная модель за API не аттестуется именем endpoint или результатами.
Сравнение H006/H008 отражает два стохастических поиска; один seed не позволяет
отнести всю разницу итогового качества только к удалению raw-полей.

Запуск: run_provider_generated_only.py --prepare-only → check_generated_only.py
→ run_provider_generated_only.py. Реестр: reports/provider_generated_only_v1/current_run.json.
