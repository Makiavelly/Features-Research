# Two-tower GraphSAGE для H&M

Поручение пользователя: отдельно кодировать пользователя и товары.
Run ID: hm_twotower_sage_seed_42_v1. Используется официальный
`upstream/examples/gnn_recommendation.py`, pinned commit описан в README.

Графовый энкодер и проекция 128→128 имеют общие веса для двух ветвей.
Forward выполняется отдельно по подграфу пользователя и по подграфу
товара. Выход товара не обусловлен ID текущего пользователя.
Товарный shallow embedding включён, как в исходной модели; ID-awareness
отсутствует. Оценка пары: dot(user_vector, item_vector). BPR loss
обучает положительную пару относительно отрицательных товаров.

Любой товар каталога получает собственный вектор даже без появления
в подграфе пользователя. Вектора валидны для указанного момента времени;
нельзя использовать test-вектора как train-признаки, история у них другая.
Значения признаков и связи фильтруются temporal sampler.

Используем seed 42, 20 эпох, channels 128, 2 слоя, sum, Adam lr=.001,
batch train 256, batch eval 128, uniform temporal sampling. Train негативы
разделяются в batch с одинаковым временем, как в официальном примере.
Ровно 2000 шагов/эпоху; исходное условие допускает 2001. Eval sampler
переиспользует training NeighborSampler, temporal strategy uniform;
RNG фиксируется отдельно для val/test, чтобы инференс был воспроизводим.
Отклонения от публикации явно указаны: train batch256 вместо512, одинseed,
особенности количества шагов и RNG. Smoke — 32 train/eval пользователей,
256 товаров, одна итерация обучения; его метрики не сравниваются со статьёй.

Итоговая оценка покрывает весь каталог 105,542 товаров. По каждому split
сохраняются user/item 128d embeddings, user IDs, время и coverage.
Model best.pt выбирается только по полному validation MAP@12.
Last.pt содержит optimizer и RNG для resume. После обучения новый процесс
загружает best.pt и проверяет полное совпадение val/test предсказаний.
Статья GraphSAGE (two-tower): val .92%, test .80% MAP@12 по пяти seeds.
Прежние ID-GNN/manual используют другой набор кандидатов, поэтому
сравнение отражает целые конвейеры, а не только архитектуру головы.

Запуск: `RelBenchGNN/launch_two_tower.ps1`, hidden WSL launcher.
Повторный запуск защищён Windows PID-проверкой и Linux flock.
Процесс не зависит от чата, но не запускается автоматически после reboot.
Результаты: results/two_tower_seed_42; отчёт reports/two_tower_v1;
журнал: WORK_LOG.md, events.jsonl, STATUS/EXPERIMENTS.
Прогресс фиксируется каждые 100 шагов; отчёт обновляется после каждой
эпохи и после независимого инференса. Итоговый exitcode=0 означает успех.

Дополнение 2026-10-15: strict-проверка полного совпадения ID не прошла
при точном совпадении MAP и расхождениях векторов не более 4.77e-7.
Она сохранена в inference_check.strict_v1.json. Новый протокол
numerical_ties_v2 проверяет близость всех векторов (atol/rtol 1e-6),
оценок рекомендаций на каждой позиции (atol 1e-5, rtol 1e-6), MAP
(atol 1e-6), а также shape/ID/уникальность. Точное совпадение ID
фиксируется отдельно. Это изменение критерия проверки, модель не меняется.
