# Малый H&M пилот: ContextGNN и сопоставимые baseline

Пользователь поручил сначала уменьшить данные для ускорения, затем
провести эксперимент. Дополнительно поручено пересчитать ручной LightGBM
и ID-GNN → LightGBM на тех же данных.

## Замороженный набор data/rel-hm-small-v1

5,000 пользователей выбраны равномерно seed42 из активных в 90 дней до
2020-09-07. Каталог — top5,000 товаров по числу транзакций выбранной
когорты за180дней до validation. Только прошлые данные влияют на состав.
История 2020-03-11..2020-09-14, 46,442 транзакции, с temporal sampling
по каждому seed time. Сохранены исходные таблицы, манифесты, контрольные
суммы и двусторонние соответствия исходных/локальных ID.

Обучающие цели — последние8 исходных недельных срезов 2020-07-13..08-31.
Цели фильтруются фиксированным каталогом; строки с пустой целью исключены.
Train 4,804 user-time, val304, test250. Покрытие исходных позитивов когорты:
train66.65%, val37.27%, test33.68%. Манифест содержит точные значения.
Это условная подзадача с ограниченным каталогом и выбранной когортой;
метрики НЕ сравниваются напрямую с полным H&M, статьёй или manual_v1.
Оценочная выборка мала: результаты предварительные.

## Нейросети

Официальный kumo-ai/ContextGNN commit
ca4a96985b7ef73c36a40da32e70710ad9b59a1e, upstream неизменён.
Модели IDGNN и ContextGNN напрямую импортируются из upstream.
2 GraphSAGE слоя,64канала, sum, neighbors32/16, ResNet encoder64×2,
batch128, Adam.001, last temporal sampling, seed42. ContextGNN RHS FUSION64.
До10эпох, до50шагов/эпоху; фактически38 шагов дают полный проход train.
Early stopping после3эпох без роста validation MAP; test только финальный.
CE для ContextGNN: сумма -log-softmax по позитивным рёбрам / batch size,
эквивалент PyG sparse_cross_entropy без обновления окружения; value/gradient
проверяются. IDGNN использует BCE по sampled товарам как upstream.
Прогнозы сортируются по logits для ContextGNN, без численного сжатия sigmoid;
IDGNN использует sigmoid sampled scores и ноль остальному каталогу.
Оценка всех5000 товаров одинакова по каталогу, но механизмы scores различны.

Явное исправление wrapper: RHS FUSION cache очищается перед каждой
оценкой/после перезагрузки весов, чтобы не использовать cache прошлой эпохи.
Иначе upstream RHSEmbedding._cached_rhs_embedding сохраняет устаревший
результат между train/eval. Исходники upstream не изменены.
Для каждого sampled графа проверяется отсутствие узлов из будущего.
Независимый процесс повторяет полный val/test после загрузки best.pt:
сравниваются scores, ranked scores, MAP и сохраняется точное совпадение ID.

## Оба LightGBM

Train: те же4,804 user-time, все позитивы + до8 history negatives и8
uniform catalog negatives с seed2026. Получилось72,813 идентичных пар
для обоих LightGBM; сортированные ключи/метки сверяются SHA256.
Ручной набор: прежние126 time-safe SQL признаков, заново вычисленные
по малому графу. Другое дерево:64представления замороженного малого
IDGNN перед линейной головой + gnn_available; нулевой вектор, если пара
не попала в sampled graph. Это in-sample train representations, не OOF;
полная стоимость такого baseline включает предыдущее обучение IDGNN.
Покрытие векторов фиксируется, отсутствие локального вектора не скрывается.

Оценка обоих деревьев по ВСЕМ5000товарам каждого val/test пользователя,
в отличие от прежнего manual_v1 с локальными кандидатами. Файлы признаков
проверяются на точное равенство декартову произведению user×catalog.
Оба LightGBM:150rounds, lr.05, num_leaves15/31 по validation, min_leaf100,
max_bin127, feature_fraction.9, bagging.8/freq1,2CPUthreads,seed42.
Сохранённые модели перезагружаются и полный инференс повторяется.
Сравнение относится к целым моделям, с разными objectives и бюджетами,
а не к изолированной причинной оценке архитектуры.

## Дополнение: существующая двухбашенная архитектура

По отдельному поручению добавлен hm_twotower_small_seed_42_v1.
Прямо используется прежний Model из RelBenchGNN/upstream/examples/model.py;
ID-awareness выключен, товарный shallow embedding включён, параметры
двух ветвей общие. Основная схема и BPR loss сохранены. Для малого
протокола channels64,2слоя,neighbors32/16,batch128,last,10эпох/patience3.
Табличный энкодер явно настроен ResNet64×2 для соответствия прочим
малым GNN, вместо большого default128×4. Это зафиксированное изменение.
Временные группы для in-batch negatives сохраняют остаточные batches:
каждая эпоха проходит все4,804train строки. Исходный TimestampSampler
отбрасывал остатки; это поведение намеренно изменено для полноты данных.
Все5000 товаров кодируются из собственных подграфов, оценка304/250
пользователей; та же задача, те же временные фильтры и subset SHA.
Оценка best checkpoint и независимый повтор после загрузки обязательны.
Результаты в ContextGNN/results/hm_small_v1/two_tower; агрегированный
отчёт дополняется, прежняя версия сохранена в before_two_tower/.
