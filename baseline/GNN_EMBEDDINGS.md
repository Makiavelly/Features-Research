# Эксперимент: замороженная ID-GNN → LightGBM

Идентификатор: `hm_idgnn_lightgbm_embeddings_seed_42_v1`.
Источник идеи: [RelBench Appendix C.2](https://arxiv.org/html/2407.20060v1).
В статье гибрид проверяется на entity regression/classification; здесь
используется наша адаптация для H&M user-item-purchase, MAP@12.

GNN не обучается повторно: используется best.pt seed 42, эпоха 19.
Forward hook перед model.head извлекает 128 чисел на товар, обусловленных
пользователем и временем. Логит головы исключён из входов LightGBM.
Пары вне sampled subgraph не имеют представления: 128 нулей и
gnn_available=0; представленные пары gnn_available=1. Всего 129 признаков.
ID пользователя/товара, время и label сохранены только для соединения,
ранжирования и оценки и не входят в признаки.

Используется прежняя выборка manual_v1: 50,000 user-time строк,
803,377 пар с теми же метками. Признаки извлекаются из графа с temporal
sampling `last` до момента прогноза. Train-представления in-sample:
GNN ранее обучалась на этих train данных, out-of-fold GNN не применяется.
Полная стоимость включает предварительное обучение GNN.

Validation/test оцениваются на точных кандидатах предыдущего инференса
GNN. При экспорте проверяется полное совпадение предсказаний исходной
головы с сохранёнными GNN предсказаниями; несовпадение останавливает запуск.
Метрики test читаются только после выбора параметров дерева.

LightGBM binary objective, seed 42, learning_rate .05, 150 rounds,
min_data_in_leaf 100, max_bin 127, feature_fraction .9, bagging_fraction .8,
bagging_freq 1, 2 CPU threads. Num_leaves 15/31 выбирается по MAP@12 на
тех же 10,000 validation пользователях (rng2026), что manual baseline.
Победившая модель загружается из model.txt перед финальным инференсом.

Запуск из корня: `wsl -d Ubuntu -- bash RelBenchGNN/run_embedding_experiment.sh`.
Не запускайте второй процесс, пока первый работает. Кэш и артефакты
отделены от manual_v1. Наличие manifest.json подтверждает успешный экспорт
всех splits; metrics.json — итоговое обучение и оценку дерева; exitcode=0 —
успешный конвейер вместе с отчётом. Незавершённый экспорт не является
полным результатом. События и прогресс записываются через tracking.py.
