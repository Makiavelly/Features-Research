# Дерево и LightGBM с вручную заданными признаками

Это наш baseline для H&M user-item-purchase, а не опубликованный
экспертный ранжирующий baseline авторов. Исходные идеи взяты из
RelBench User Study: `expert_upstream/hm/user-churn/feats.sql` и
`expert_upstream/hm/item-sales/feats.sql`. В них нет готового набора
для user-item-purchase. Реализация и адаптация: `manual_features.py`.

126 явно заданных признаков:

- характеристики пользователя: возраст, членство, активность, подписка;
- характеристики категории/цвета/секции товара;
- число, сумма, средняя цена, уникальные товары и канал покупок
  пользователя за всю историю и пять отдельных предыдущих недель;
- наиболее частые категории/цвета пользователя;
- продажи, средняя цена, уникальные покупатели и средний возраст
  покупателей товара за предыдущие недели; накопленная популярность;
- вручную добавлены число покупок пары user-item, давность покупки,
  предпочтения категорий за 28 дней, совпадения товара с предпочтениями,
  отношение цены товара к среднему чеку пользователя и календарь.

Агрегаты используют только t_dat <= момент предсказания, как временной
семплер ID-GNN. Исходные экспертные SQL используют строгую границу <;
это изменение явно принято для одинаковой доступности истории.
Будущие транзакции не используются. Пользовательские/товарные ID,
метка и timestamp исключены из входных столбцов модели. Текстовые
эмбеддинги, GNN-представления и прогнозы GNN не используются как признаки.
Некоторые сложные rolling-признаки исходного исследования не перенесены;
используется адаптированное подмножество плюс наши признаки пары.

## Общие кандидаты

Для каждого seed дерево ранжирует ровно тот набор товаров, который
получен при независимом инференсе соответствующей ID-GNN. Он зависит
от прошлой истории/семплера, а не от будущих целевых товаров. В набор
включаются и технические нулевые-score товары, выбранные GNN при
нехватке соседей. Сравнение основного scoring выполняется на общих
кандидатах; это не отдельное исследование генерации кандидатов.
Если pools различаются между seeds, признаки вычисляются для их
объединения, но оценка фильтруется отдельно для каждого seed.

## Обучение и подбор

- Фиксированная выборка 50,000 user-time строк из train (seed 2026).
  Все положительные товары и до 8 отрицательных из истории плюс
  8 из каталога; отрицательные исключают все положительные товары.
- Исторические агрегаты используют весь доступный прошлый снимок,
  но supervised train меньше, чем у ID-GNN. Это ограничение бюджета,
  а не равный объём обучения; обязательно учитывать при интерпретации.
- Одиночное DecisionTreeClassifier: depths 8/12/16, min_leaf=100,
  balanced class weights. Категории кодируются one-hot.
- LightGBM: leaves 15/31, 150 деревьев, lr=.05, min_leaf=100;
  категории имеют встроенное categorical-кодирование.
- Конфигурация выбирается по MAP@12 на фиксированных 10,000
  validation пользователей. Тест не участвует в подборе.
- Пять seeds 42..46, выбранная конфигурация фиксирована.
- Итоговая оценка на полном validation/test. Для равных оценок
  порядок определяется article_id; ручной tie-break по цели отсутствует.
- Модель сохраняется и заново загружается перед итоговым инференсом.

Численные параметры и результаты подбора: results/manual_v1/config.json.
Итоги и прогнозы: results/manual_v1/{decision_tree,lightgbm}/seed_*.
Кэш Parquet-признаков читается пакетами: весь test не загружается в RAM.

## Что было в статье (MAP@12, проценты)

| Метод | Validation | Test |
|---|---:|---:|
| Global popularity | 0.36 | 0.30 |
| Past visit | 1.07 | 0.89 |
| LightGBM: сырые признаки + история/популярность | 0.44 | 0.38 |
| RDL GraphSAGE | 0.92 | 0.80 |
| RDL ID-GNN | 2.64 | 2.81 |

Источник: [RelBench, таблица 8](https://arxiv.org/html/2407.20060v1).
Экспертный user study касается других целей (классификации/регрессии).
Значение LightGBM 0.38% нельзя приписывать нашему набору 126 признаков.
Фактические наши метрики добавляются в общий отчёт после запуска;
отсутствующий результат показывается как ожидаемый, не как ноль.

## Проверки и запуск

`test_manual_features.py` проверяет отсечение будущих данных,
границу cutoff, одну строку на пару и исключение ID/метки из признаков.
`check_real_snapshot.py` проверяет SQL на настоящем H&M без обучения.
Полный запуск автоматически встроен в postprocess.py после пяти
проверок инференса GNN. Он использует CPU и выполняется последовательно,
чтобы не отнимать RAM у обучения GNN.


## Изменение плана 2026-10-14: один seed

По просьбе пользователя для ускорения используются только seed 42: ID-GNN,
DecisionTree и LightGBM. План задан в RelBenchGNN/experiment_plan.json.
Seed 42 завершил 20 эпох; начатый seed 43 остановлен, 44–46 исключены.
Артефакты остановленного запуска сохранены, в сравнении не используются.
После seed 42 выполняются независимый инференс, деревья и графики.
Это одиночный локальный результат в сравнении со средним пяти запусков
статьи; стандартное отклонение локальных seeds не оценивается.
Предыдущие описания пяти локальных запусков заменены этим решением.
