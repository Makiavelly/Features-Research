# Воспроизведение RelBench: H&M / user-item-purchase

Цель: обучить RelBench ID-GNN и сравнить MAP@12 с таблицей 8 статьи
https://arxiv.org/abs/2407.20060. Опубликовано: validation 2.64%, test 2.81%
(стандартные отклонения по пяти запускам: 0.00 и 0.01 процентного пункта).
Значения в JSON результатов хранятся как доли; для процентов умножайте на 100.

## Запуск на этом компьютере

Используется Ubuntu WSL2 и локальное окружение `.venv-wsl`, CUDA 11.8,
PyTorch 2.2.2. Системный Python и драйвер GPU не меняются.

Из PowerShell в корне проекта:

```powershell
wsl -d Ubuntu -- bash RelBenchGNN/setup_wsl.sh
wsl -d Ubuntu -- bash RelBenchGNN/run_experiment.sh smoke
wsl -d Ubuntu -- bash RelBenchGNN/run_experiment.sh full
```

Полная последовательность в фоне (проверка данных, простые baseline,
smoke, пять полных запусков):

```powershell
.\RelBenchGNN\launch_background.ps1
.\RelBenchGNN\check_status.ps1
```

PID Linux-процесса: `logs/pipeline.pid`, итоговый код завершения:
`logs/pipeline.exitcode` (появляется только после выхода процесса).
Повторный запуск full продолжает завершённые эпохи из last.pt;
уже завершённые seeds пропускаются.

Повторный вызов setup пересоздаёт только локальное виртуальное окружение.
Для уже настроенного окружения этот шаг не нужен.

`run_idgnn.py` — копия официального примера с локальным путём к данным,
сохранением checkpoint, JSON метрик, NumPy и CSV предсказаний. Генератор
адаптации: `prepare_runner.py`. Исходный репозиторий не изменён.

## Протокол и ограничения сравнения

- 20 эпох; Adam, learning rate 0.001; batch size обучения 512;
  128 скрытых каналов; 2 слоя GraphSAGE; суммирование сообщений;
  до 128 и 64 соседей на двух шагах; ID awareness.
- `temporal_strategy=last`: это значение в опубликованном коде 2024 года
  и в актуальном примере. В таблице 9 статьи указано `uniform`.
  Основной запуск воспроизводит код; расхождение со статьёй явно сохранено.
- Пять выбранных нами seeds: 42, 43, 44, 45, 46. Статья сообщает пять запусков,
  но точные seeds в проверенных материалах не указаны.
- Валидация и тест полные; batch size оценки 128 уменьшает расход GPU памяти
  относительно исходного 512. Обучающий batch size остаётся исходным.
- Не более 2000 заявленных шагов на эпоху. Сохранена исходная проверка
  `steps > max_steps_per_epoch`, поэтому при длинном loader фактически
  выполняется 2001 шаг (особенность исходного примера).
- Выбор лучших весов по validation MAP, тест только после выбора.
- Разбиения по времени: validation 2020-09-07, test 2020-09-14.
  Граф строится с данными только до test_timestamp; временной семплер
  ограничивает историю датой каждой обучающей/оценочной строки.
- Современный загрузчик и опубликованный Parquet-снимок используются
  вместо устаревшего сервера данных. Это воспроизведение протокола и
  архитектуры, без обещания побитового совпадения с окружением авторов.
- Smoke — только проверка загрузки/обучения/оценки на нескольких строках.
  Её метрики нельзя сравнивать со статьёй.

## Артефакты

- `cache/`: преобразованные признаки таблиц для повторного использования.
- `logs/seed_*.log`: вывод полных запусков.
- `results/seed_*/config.json`: параметры конкретного запуска.
- `results/seed_*/best.pt`, `last.pt`: лучшие веса и последний checkpoint.
- `results/seed_*/history.json`: loss и validation MAP по эпохам.
- `results/seed_*/metrics.json`: итоговые метрики (только после завершения).
- `results/seed_*/test_predictions.npy`, `val_predictions.npy` и
  `predictions.csv`: предсказания в порядке официальных label-таблиц.
- `results/summary.json`: среднее и стандартное отклонение завершённых запусков.
- `requirements.lock.txt`: фактически установленные версии библиотек.

GloVe (Global Vectors for Word Representation) — исходный текстовый
кодировщик примера RelBench: 300-мерные векторы слов и усреднение токенов.
Его локальный снимок хранится в `../data/models/glove`, отдельно от H&M.
Он используется для текстовых описаний, а не вместо обучаемой ID-GNN.

`baseline/run_simple.py` воспроизводит popularity/past-visit на полном
validation/test и сохраняет метрики в `baseline/results/simple_metrics.json`.
Экспертные признаки доступны для user-churn и item-sales; их перенос
на ранжирование требует отдельной адаптации и не является исходным
экспертным ранжирующим baseline из статьи.

## История и контекст других сессий

В корне проекта ведутся `CONTEXT.md` (решения и цели), `STATUS.md`
(этап и прогресс), `EXPERIMENTS.md` (результаты), `WORK_LOG.md` (история).
Машиночитаемые версии — `experiments/state.json` и `events.jsonl`.
Все времена московские. События дописываются, прошлые результаты
не удаляются. Новый протокол получает новый run_id и каталог артефактов.

Новые запуски сами записывают этапы, эпохи, ошибки и итоговые метрики.
Дополнительно `monitor.py` раз в 30 секунд проверяет процесс, progress
в логе и history.json; он поддерживает уже работающий seed 42,
который был запущен до добавления встроенного журналирования.
Монитор стартует автоматически из launch_background.ps1.

Проверка файлов — последняя записанная информация, а не гарантия,
что компьютер не был выключен. Перед продолжением сверяйте PID/логи.

## Проверка инференса и наглядный отчёт

После всех пяти запусков summarize.py автоматически вызывает postprocess.py.
Для каждого seed отдельный процесс загружает best.pt и повторяет полный
validation/test с теми же конфигурацией и кодом графа/оценки. Проверяются
конечность logits, форма и допустимость top-12, отсутствие дубликатов ID,
разница MAP с сохранённой оценкой не более 1e-6 в долях. Побитовое
совпадение предсказаний фиксируется отдельно, но не является обязательным
из-за численной недетерминированности CUDA. В отчёте есть время инференса
и количество пользователей в секунду (включая семплинг/чтение batch).

Файлы проверки: results/seed_*/inference/inference_check.json и логи
logs/inference_seed_*.log. Наглядный отчёт: ../reports/relbench_hm_v1/report.md,
CSV-таблицы, сравнение метрик PNG/SVG, кривые обучения и гистограмма
AP@12 пользователей после проверенного инференса. Пока обучение идёт,
монитор обновляет промежуточный отчёт после каждой завершённой эпохи.
Незавершённые запуски не отображаются как нулевой результат.

Повторная сводка без запуска инференса: summarize.py --summary-only.
Повторная проверка/отчёт: postprocess.py. Только графики: build_report.py.


## Изменение плана 2026-10-14: один seed

По просьбе пользователя для ускорения используются только seed 42: ID-GNN,
DecisionTree и LightGBM. План задан в RelBenchGNN/experiment_plan.json.
Seed 42 завершил 20 эпох; начатый seed 43 остановлен, 44–46 исключены.
Артефакты остановленного запуска сохранены, в сравнении не используются.
После seed 42 выполняются независимый инференс, деревья и графики.
Это одиночный локальный результат в сравнении со средним пяти запусков
статьи; стандартное отклонение локальных seeds не оценивается.
Предыдущие описания пяти локальных запусков заменены этим решением.
